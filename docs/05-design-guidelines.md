## 9.1 再利用と責務

Astroの静的HTML、標準のリンク・見出し・リストを使う。独自Dialog/Select/Popover/DnD/アニメーションを作らない。サイト固有のレイアウトだけを所有し、不要なvendorコピーやregistry生成をしない。pnpm-lock.yamlに統一し、同一用途のUI依存や競合トークンを重ねない。見栄えのために機能を増やさない。

## 9.3 情報構造

一覧は日付、タイトル、要約。詳細は公開・更新日、タイトル、概要、本文、出典。カテゴリは実際に必要な場合のみ追加する。情報量の少ない現状は1カラムとし、補助ナビのために本文を狭めない。ヘッダーは通常フローでスクロール中の高さ変更をしない。

巨大なヒーロー、ぼかしたグラデーション、蛍光色、過剰なカード、統計パネル、装飾ボタン、サイドバー、Eyebrowや英大文字の飾り見出しを置かない。記事0件を架空ニュースやランキングで埋めない。空状態を埋める目的の大きな固定余白も設けない。

## 9.4 文案

- 簡潔な日本語を使い、抽象的比喩、誇張、過度な口語、宣伝調、造語を避ける。
- 中点「·」を区切りとして使わない。タグライン、重複ラベル、装飾的バッジ、不要なヘルパー文を削る。
- 必須ラベル、入力制約、エラー、アクセシビリティ説明は削らない。説明を足す前に階層と配置を直す。
- 「続きを読む」を濫用せず、記事タイトルを識別できるリンク名にする。
- 架空の試合結果・選手関係・アクセス数を置かない。事実と考察を区別し出典を記す。
- 検証用記事は検証と明示し、公開用データと分離する。

文案の見直し資料は https://zenn.dev/todesking/articles/5bc43f449ecdf6 。

## 9.5 デザイントークンと整列

正本はsrc/styles/global.css。

| 役割 | 値 |
| --- | --- |
| 背景 / 本文 / 補助文字 / 罫線 | Radix sand-1 / sand-12 / sand-11 / sand-7 |
| リンク / フォーカス | Radix jade-12 / jade-10 |
| 小文字 / 本文 / 見出し / タイトル | .875 / 1.0625 / 1.5 / 2.5rem。標準16px設定で14/17/24/40px。768px以下はタイトル32px、480px以下は見出し22px。各画面4階層 |
| 余白 | 8/16/24/32/48pxを共通変数化。モバイル外側20px |
| 全体幅 / 本文幅 | 最大960px / 704px |
| 罫線 | 0.5px。消える端末で実証された場合のみ理由を記して調整 |
| レスポンシブ | 全幅で日付→見出し→要約を縦積み。768px以下は外側24px、480px以下は20px |
| 操作領域 | ナビ・一覧タイトル・一覧へ戻る・フッターの独立リンクは高さ44px以上 |

通常のUI文字は12px未満にしない。サイズを増やす代わりにウェイト・余白・配置で階層を示す。ページごとの独自色を増やさず、状態は色だけに頼らない。危険操作・入力状態は現状存在しない。

中央のマストヘッドとナビ、本文内の日付・タイトル・要約の左端、和文/英数混在、長いURL、画像比率を375/768/1280pxで確認する。横はみ出しや切れを許容しない。コードブロックだけは局所スクロール可能とする。影、ランダムな角丸、カード左の色線は使わない。将来角丸を入れる際は親子を同心に揃える。

## 9.6 動きと操作

装飾的なアニメーション、スクロール演出、ページ遷移演出を追加しない。現在アニメーション/transitionは0。将来機能上必要になった場合だけease-out/約250msを候補とし、prefers-reduced-motionで抑制する。CSSで足りる場合はMotionを追加しない。

リサイズ、ドラッグ、グローバル状態は必要になるまで導入しない。不要な確認ダイアログやトーストを増やさず、エラーや結果は操作位置へ示す。design.howとtransitions.devは動きが必要になった場合のみ確認し、不要な外部スキルはインストールしない。

## 9.7 UX原則と読者操作

| 一次資料 | このサイトでの適用 |
| --- | --- |
| https://lawsofux.com/ | 選択肢過多を避け小さいナビにする。関連する日付・タイトル・要約を余白でまとめる。独立リンクをタップしやすくする。 |
| https://www.nngroup.com/articles/ten-usability-heuristics/ | 一貫したリンクと見出し、短い空状態、404から一覧へ戻る導線を用意する。 |
| https://design-system.service.gov.uk/accessibility/ | ライブラリ採用だけでアクセシブルと扱わず、キーボード・文字・寸法を実画面で検証する。 |
| https://inclusive-components.design/cards/ | 一覧を意味のあるリストと見出しにし、記事タイトルをリンク名にする。行全体のJSクリックや不要なカードUIを追加しない。 |
| https://developer.apple.com/design/human-interface-guidelines/layout | 公式Markdown本文を取得し確認。見出し・日付・本文の整列と視覚階層、画面幅に適応する折り返しへ反映。Appleアプリ固有の素材や装飾をWebへ持ち込まない。 |

semantic HTML、h1からの見出し順序、Tab/Enter、可視フォーカス、本文へ移動、明確なリンク名、画像alt/寸法/lazy loading、タップ領域と文字拡大を確認する。フォームがないためlabel・入力エラーは現在非該当。将来追加する場合は必須。不要なARIAを足さない。

上記は実装ルールであり、スクリーンリーダー監査や全ての支援技術での適合を保証するものではない。未検証項目は08へ明記する。

## 今回のレイアウト変更と比較

中央マストヘッド案と左サイドバー案を、同じ検証原稿・配色でローカル比較した。3リンクのために横幅を消費する左サイドバー案は採用せず、中央マストヘッド案を実装した。比較ページと原稿は.audit内だけに置き、公開しない。

従来の横並びヘッダーを、中央のセリフ体サイト名と罫線で囲んだ独立ナビへ変更。一覧は日付列と見出し列の横組みをやめ、日付・見出し・要約を縦にまとめた。詳細には概要を表示し、本文と区切った。出典は本文末尾の独立した領域へ配置。404を含む長いh1はtext-wrap:balanceで折り返す。配色はSand/Jade、タイトルは40pxを基本とする。参照先の商標・ロゴ・コードは複製していない。

## コンポーネントの実採用状況

package.jsonとsrcを照合。使用中はRadix ColorsのCSSパレットだけで、Radix Primitives/Themes・KumoのUIコンポーネントは未使用。AstroのHTMLテンプレートとサイト固有CSSで公開画面を構成している。「Radixのコンポーネントを使用済み」とは表現しない。原依頼9.2の公開側Astro/HTML基本、KumoはReact管理画面候補という条件に基づく判断。

2026-10-25の明示依頼によりMarkdown表示テスト1件を公開用原稿へ追加した。ニュースと誤認しないタイトル・要約・本文を記載。以前の「検証原稿はすべて非公開」という記録は、この追加原稿には適用しない。自動テストfixtureと以前の.audit内原稿は公開対象外のまま。
